Overview

OpenUtility is designed around small, focused utilities that run in the browser whenever the operation can be performed locally. The interface is intentionally consistent: discover a tool, inspect its detail view, run it, copy or download the result, and return to your workflow.

Most supported tools do not need an account or a server-side request. Treat URLs containing tool input as public data and avoid putting secrets into shared links.

Guides

Open a tool directlyUse /?tool=json-formatter to launch a tool from a bookmark or workflow.
Use Tool ChainsAdd compatible utilities to a chain from the tool detail experience and keep multi-step transformations together.
Work offlineAfter the application shell and tool assets are cached, supported client-side utilities can continue working without a network connection.
Share a workflowUse the tool detail Share action to copy a stable entry URL. Do not share sensitive input through query parameters.

Privacy model

OpenUtility prioritizes client-side processing. A local tool can process its input without uploading it to OpenUtility infrastructure. Third-party libraries may still be loaded when a tool requires them, so review the tool and privacy documentation before using sensitive data.

Do not put passwords, private tokens, personal data, or other secrets into URLs, screenshots, or shared configurations.

Shareable links

Every tool can be addressed with a simple query parameter, such as /?tool=base64. This makes bookmarks, documentation links, and workflow entry points predictable without requiring an account.

Contributing

OpenUtility is open source. Contributions can improve tools, accessibility, documentation, performance, and the overall developer experience.
